# Bahamas P1 inspection contract

The P1 collection holds provisional evidence for read-only inspection. It does not create or update tasks, evidence drafts, agent judgments, human decisions, PI acceptances, exports, or map output. The public contracts are `schemas/inspection-case.v1.schema.json` and `schemas/inspection-collection.v1.schema.json`; strict TypeScript validation and adaptation live in `convex/lib/inspectionCollection.ts`. Public examples and tests are synthetic.

A case projection retains the source snapshot date and original definition version and hash. Each source records its stable reference and family, locator, publisher, publication date, retrieval time, returned database date, access result, licence note, copy permission, display permission, optional original-byte hash, and optional permitted extract. An extract requires both copy and display permission to be `permitted`; either `needs_review` or `restricted` decision allows metadata and a locator only. Candidate links retain their basis and disposition without turning proximity into identity. Claims retain wording, described and observed dates, supporting source references, and null geometry for unresolved locations. Agent assessments keep requested and reported models distinct, with a reason when the reported model is unknown. At ingest, a non-null context task must exist in the deployment, and a named evidence version must exist and belong to that task. The projection remains provisional.

The adapter accepts only its declared interchange fields and produces a field-mapping and source-permission report. Unsupported fields, missing source links, invalid geometry, unsafe URLs, unpermitted extracts, and personal-detail hits fail before a receipt is written. The exhaustive key and value screen reuses `convex/lib/firstPass.ts`; a further conservative clergy and tenure screen holds those passages for human restriction or redaction. The shared detector recognises New Zealand telephone numbers only, so the inspection screen also refuses North American numbering-plan forms, including Bahamas `+1 242`, `(242)`, unseparated ten-digit numbers and space-separated seven-digit local numbers. Four-digit years and counts remain allowed. Source locators, and a candidate link's `osm_ref` or `candidate_ref` holding an exact OpenStreetMap element reference (`node`, `way` or `relation` followed by its id, bare or as an `openstreetmap.org` URL), are exempt from the North American pattern, because their ids can have ten digits; the shared detector still screens them. Every other value is screened for the North American pattern both as written and after compatibility normalisation and percent-decoding, so full-width or encoded digits do not pass. Every refusal names the field or undeclared key by position and never copies its value. An operator must review the mapping, omissions, findings, unsupported records, and source permissions from the private adapter before an import. The public adapter contains no retained research cases.

`inspection_object_receipts` adds a private immutable index for case and collection objects. Each receipt uses `object-receipt.v1`: a SHA-256 address over exact sorted, compact, ASCII JSON bytes with one final newline, a namespace-qualified receipt ID, and the `convex_only` storage tier. Identical retries return the existing receipt. Once a logical case or collection has a receipt, changed bytes require a new hash and already receipted parents for that same object; a second parentless root is refused. A collection receipt requires each case receipt and records exact membership; the collection and its members must share source snapshot and definition context. The internal ingest is behind the maintained internal-agent gate. Reviewer receipt reads require an active reviewer, curator, administrator, or PI; recovery is an internal query. A known object hash is not an access token, and no source-object bytes are exposed by this contract.

`restoreInspectionCollection` verifies hosted object bytes, hashes, collection membership, and case projections from a clean cache. The synthetic test restores from versioned project-controlled fixture objects in `scripts/agent_research/fixtures/inspection-objects/` after clearing its cache; it verifies round-trip reconstruction and tamper detection. The operational hosted-object recovery drill remains outstanding; P1's synthetic drill does not satisfy it. Operational P2 requires a private hosted-object adapter, read-back verification, a clean-cache drill against the actual hosted copy, and role checks for every source-object request. Convex receipts stay at `convex_only` until an independent verified copy is recorded under the maintained storage contract. P2 supplies authenticated pagination, detail queries, and portal controls; P3 supplies definition-compatible review and export changes.
