# Instructions for Guy — census tables for the Vanuatu map

Kia ora Guy — this page is the durable copy of how to send census
data so it lands on the map quickly and with your work credited. It
supersedes any email version.

## What has already worked

Your scan of the print-only 1999 Main Report went from email to the
live map in one evening: Table 2.10 was transcribed at province level,
validated exactly against its own totals and the national series, and
the Vanuatu map now runs 1999–2020 with the source credited "digitised
by Guy Lavender Forsyth". The scan itself is archived durably in the
project's private storage.

## Sending tables — the recipe

1. **Format.** Send .xlsx or .csv, one census table per sheet (or per
   file), named for what it is, e.g. `religion_by_AC_1979`.
2. **Cite the source on each table.** A notes cell or README tab per
   table: census year, volume, table number, page — e.g. "1979 Census
   Report Vol. 1, Table 5.3, pp. 102–104".
3. **Say what you did.** Mark each table "verbatim" or "harmonised";
   if harmonised, one or two lines on the rules (e.g. "NTM folded into
   Other before 1989", "Torres + Ureparapara merged").
4. **Keep original labels.** The census's own religion categories and
   geography names as printed; your harmonised labels in an extra
   column beside them, never replacing them.
5. **Name the geography vintage.** E.g. "1999 ACs as in the 1999
   report". Note for pre-1994 censuses: those years used the eleven
   local-government regions, not the six provinces — if your sheets
   carry a crosswalk to provinces or to modern ACs, include it; it is
   as valuable as the counts.
6. **Blanks and totals.** Missing values stay blank (not 0, not "NA");
   include the printed totals even where they look inconsistent — we
   validate against them and document discrepancies rather than
   silently fixing them.
7. **Scope.** Area Council level and up only — nothing household- or
   individual-level by email, as you said.

Email attachments to JB; he drops them into the pipeline. Every
delivery is hashed, validated against published totals, archived, and
credited to you in the data manifests and changelog.
