# Sri Lanka DSD boundary hunt

Recorded 2026-07-12 by a probe lane, extending the boundary blocker in `dsd-probe.md`. Every claim below comes from a source fetched during this probe; the source URL sits beside each candidate. No files were downloaded (all vector archives exceed the 50MB cache limit or were queried metadata-only); no build was attempted.

## Verdict: HELD-confirmed

No openly licensed, per-vintage Divisional Secretariat Division (DSD) boundary layer matching either census frame exists. The 2012 census frame needs 331 DSDs and the 2024 frame needs 340. The hunt found four distinct DSD geometries in circulation — geoBoundaries 330 (2020), COD-AB 339 (2022), the NSDI/Survey Department live layer 332 (current), and the Census Department's own 331 reference — and **none matches either census count**. The 2024 frame (340) has no located vector geometry at all. No documented aggregation path exists: recovering 331 from 340 by union (the Montenegro exact-partition precedent) would require the 340 geometry with parent attribution, and that layer was not found in any form.

Two findings change the shape of the unblock, so record them before re-holding. First, the NSDI/Survey Department live layer carries `ds_division_code` values drawn from the Department of Census and Statistics (DCS) administrative-code system, which opens a code-based census join that would sidestep the roughly 68 transliteration divergences per wave — but the layer is 332 features (a fourth frame) and its licence is unconfirmed. Second, the DCS itself holds a 331-DSD digital frame (it rendered the 331 per-district risk maps) and the 2024 census ran on a 340 frame, so the two exact per-vintage layers exist inside DCS; the department publishes only "All Rights Reserved" PDFs of them.

### Concrete unblock ask

Obtain the two DCS census-year DSD vector layers direct from the Department of Census and Statistics: the 2012 frame (331 divisions) and the 2024 frame (340). These are the only geometries that match the extracted census tables one-to-one. Failing a DCS data grant, the fallback route is a licence determination on the NSDI/Survey Department layer (332 features, code-joinable) from ICTA/NSDI's National Data Sharing Policy: if that layer is confirmed CC-BY or equivalently open, it becomes a usable 2012-adjacent base — still off by count (+1 versus 331, with Ampara short one division) and still supplying no 2024 frame. Absent either, the only confirmed openly licensed vectors (geoBoundaries 330 under CC BY 3.0 IGO, COD-AB 339 under CC BY-IGO) match neither census frame and admit no union path.

## Notes on the aggregation path

The Montenegro precedent recovers an older frame by unioning a newer, finer layer whose sub-divisions carry parent attribution. Sri Lanka's relevant splits run 2012→2024 (Nuwara Eliya 5→10, Galle 19→22, Ratnapura 17→18, Ampara reshuffled at equal count). Recovering the 2012 frame (331) by union therefore needs the 2024 geometry (340) with parent codes — and no 340-feature DSD geometry was located in any repository. COD-AB's `valid_on`/`valid_to` fields could in principle encode a split history, but the layer is a single 339-feature snapshot with `valid_to` unpopulated, so it decomposes to neither census frame. No aggregation path is available from any open source found.

## Code-concordance mitigation (does not lift the hold)

The NSDI `ds_division_code` follows the DCS administrative-division code system published at https://www.statistics.gov.lk/qlink/AdminDivCode (district-prefixed four-digit codes; Ampara district 52 → DSDs 5203…5251, Nuwara Eliya district 23 → 2303…2315). A concordance of census name → DCS code → NSDI feature would remove the transliteration matching (Matugama/Mathugama, Bentota/Benthota, Monaragala/Moneragala) and resolve the unnamed 2012 Mannar division by code. This mitigation depends on (i) an open licence for the NSDI layer and (ii) accepting its 332-frame count mismatch; it does not, on its own, produce a per-vintage 331 or 340 geometry.
